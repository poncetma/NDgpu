# Unstructured mesh scope and limitations

NDgpu's unstructured path is a **restricted cell-centred two-point-flux
approximation (TPFA)**, not a general-purpose Gmsh or CAD-mesh solver. Gmsh is
an input format for meshes that already satisfy the requirements below; a mesh
being readable does not establish that the diffusion discretisation is
consistent on it.

The primary intended use is controlled local refinement of an otherwise
well-behaved 2-D triangular mesh, such as resolving HP-MR control-drum absorber
bands without refining the full core. Regular conforming triangular,
quadrilateral, tetrahedral, hexahedral, and prismatic meshes are also useful
when they satisfy the TPFA geometry assumptions. Arbitrary exported CAD meshes
should not be assumed to work accurately.

## Numerical geometry requirements

For an interior face shared by cells `i` and `j`, NDgpu uses

```text
D_harmonic * face_measure / distance(cell_centroid_i, cell_centroid_j)
```

with an analogous centroid-to-face-centroid distance at a boundary. This is a
conservative, symmetric construction, but TPFA is consistent only when the
line between the two cell centres is normal, or close to normal, to their
shared face. In practice:

- orthogonal Cartesian quads and hexes are suitable;
- regular or mildly distorted simplex/prismatic meshes can be suitable after
  a refinement study against a trusted reference;
- strongly skewed, non-orthogonal, warped, sliver, or badly graded cells are
  outside the verified accuracy envelope;
- conservation and solver convergence do not prove spatial accuracy on such a
  mesh;
- NDgpu does not currently calculate an orthogonality/skewness metric or reject
  a poor-quality mesh automatically.

The 2-D assembler uses the mean of a cell's vertices as its centre. This is
exact for triangles and parallelograms, but is not the area centroid of a
general quadrilateral. The 3-D assembler assumes linear convex or star-convex
cells with consistently ordered, planar bounding faces. Concave cells,
polyhedra, pyramids, and warped higher-order geometry are unsupported.

A non-orthogonal correction, MPFA/mimetic finite-volume method, or finite
element method would be needed before claiming robust support for general CAD
meshes.

## Gmsh reader contract

`read_gmsh()` is a small legacy-format reader, not a complete Gmsh parser.

| Property | Current support |
|---|---|
| File format | Gmsh 2.2 ASCII only |
| 2-D cells | first-order triangles (type 2), quads (type 3) |
| 3-D cells | first-order tetrahedra (type 4), hexes (type 5), prisms (type 6) |
| Material regions | first element/physical tag on each retained cell |
| Boundary regions | not retained; one boundary condition is applied globally |
| Embedded 2-D surfaces | unsupported; 2-D coordinates are projected to `x, y` |
| Mixed dimensions | volume cells win; lower-dimensional elements are ignored |
| Gmsh 4.x, binary, higher-order cells | unsupported |
| Pyramids, polygons, general polyhedra | unsupported |

The reader also assumes the common Gmsh 2.2 layout with two element tags and
node identifiers that fit the declared node table. Unsupported elements are
ignored rather than converted. Inspect `mesh.n_cells`, `mesh.cell_tag`, cell
measures, connectivity, and material volumes after import; do not treat a
successful parse as validation. Convert a Gmsh 4.x or complex model explicitly
to a controlled 2.2 ASCII mesh before use.

## Local refinement contract

The 2-D assembler supports nonconforming interfaces created by recursive
midpoint bisection. A coarse edge can be matched to fine edges at any dyadic
depth, and each fine leaf is coupled conservatively to the coarse cell. This is
the mechanism used by the HP-MR drum-band refinement study.

The current limits are important:

- hanging nodes must lie at recursively exact edge midpoints;
- arbitrary split ratios and unrelated overlapping edges are unsupported;
- coordinate matching is tolerance-based and intended for meshes generated by
  the same controlled refinement pipeline;
- non-manifold connectivity is unsupported;
- 3-D hanging-node interfaces are unsupported; 3-D assembly is conforming
  only.

Local refinement reduces cell count, but deep grading can worsen the condition
number and increase Krylov iterations. More refinement levels do not therefore
guarantee a faster solve. The HP-MR study found that a shallower globally finer
base mesh was faster than a smaller mesh with a deeper hanging-node hierarchy.
See [hpmr_drum_refinement.md](hpmr_drum_refinement.md) for the measured result.

## Physics and execution scope

`MeshModel` and `UnstructuredDiffusionSolver` currently provide:

- steady, forward, multigroup diffusion k-eigenvalue calculations;
- one CPU or one CUDA GPU through NumPy/CuPy;
- cell material assignment by imported volume tag or cell-centroid selection;
- one albedo/Robin boundary condition applied to every exterior face;
- low-level two-material volume mixing through
  `UnstructuredDiffusionSolver`.

They do not currently provide unstructured transient or adjoint solves,
SPN/SDPN, per-boundary physical conditions, thermal feedback, mesh motion,
distributed-memory/MPI execution, or multi-GPU partitioning. `MeshModel` does
not expose the low-level volume-mixing arrays. Centroid-based material painting
also does not geometrically clip curved interfaces; use explicit volume mixing
when partial-cell material volume matters.

There is one deliberately narrower transient/MPI extension:
`ExtrudedMeshGrid` tensor-products a controlled 2-D mesh with identical uniform
axial layers. Its dedicated diffusion solvers support transient stepping and
axial MPI decomposition without claiming general 3-D unstructured support.
The radial topology must be identical in every layer; it is intended for the
locally refined prismatic HP-MR model, not arbitrary 3-D Gmsh input.

The GPU adjacency uses ELLPACK storage. Memory and work scale with
`n_cells * maximum_cell_degree`, so a few abnormally high-degree cells can
create substantial padding. The available Jacobi/Neumann preconditioners can
also become iteration-bound on strongly graded meshes.

## Verification envelope

Automated tests cover:

- equivalence with structured diffusion on orthogonal quad and hex meshes;
- analytic convergence on structured orthogonal hex meshes;
- regular triangular/simplex and mixed conforming element cases;
- recursive 2-D midpoint refinement and HP-MR local drum-band refinement;
- CPU/GPU execution of the same assembled TPFA operator.

There is no general skew-mesh convergence suite, no 3-D nonconforming test, and
no broad collection of CAD-exported Gmsh meshes in continuous integration. The
VVER-440 Gmsh comparison depends on an external mesh and is skipped when that
file is unavailable.

## Preflight checklist

Before using a new unstructured mesh for reactor conclusions:

1. Confirm that it satisfies the reader table above, or assemble `Mesh`
   directly from supported linear cells.
2. Plot the mesh and inspect cell orientation, skewness, grading, duplicate
   nodes, non-manifold faces, imported tags, and boundary coverage externally.
3. Check for positive cell measures and the expected number of retained cells.
4. Verify material volumes and use volume fractions rather than centroid
   painting at thin or curved interfaces.
5. Compare `k_eff`, leakage, reaction rates, and control worth with a trusted
   method on a reduced model.
6. Repeat with global and local refinement. Require the engineering quantity of
   interest, not just the eigenvalue residual, to converge monotonically.
7. Compare CPU and GPU results before a production campaign.

For a new mesh family that violates the TPFA requirements, use the structured
or triangular NDgpu paths when possible, or use an FEM/MPFA-capable solver
rather than relying on successful Gmsh import.
